# 旅游攻略生成规范

质量基准：**`大阪关西5天4夜攻略.html`**（配套纯文本版 `大阪关西5天4夜攻略.md`）。动手前先读它找感觉；本目录的 `template.html` 是从它抽出的空骨架（完整 CSS + 弹窗引擎 + 各区块占位），新攻略从拷贝它开始，不要从零写样式。

## 交付物（缺一不可）

1. `目的地X天Y夜攻略.html` —— 单文件、零依赖、内联 CSS/JS，手机可直接打开。
2. `目的地X天Y夜攻略.md` —— 同内容的 Markdown 纯文本版（表格为主，方便微信/备忘录查看）。
3. 在 `index.html` 的卡片列表里登记新攻略（照抄现有卡片格式）。
4. 图片放 `images/`（美食图放 `images/food/`），署名信息写入 `images/credits.json` 与 `images/food/credits.json`。

## 调研流程（先调研，后写作）

- 原始资料、分主题笔记放 `research/`（如 `kyoto.md`、`nantong-food.md`）；抓取的原始数据放 `research/_raw/`。
- **来源分级**，写进页面「行前必查」区块：
  - A 级·官方（运营方官网：票券价格、开闭馆、灯光/夜枫日程）——只用官网数字；
  - B 级·机构（交通局、气象厅平年值、景区公告）；
  - C 级·媒体（排队情况、机位、季节活动）——参考即可；
  - D 级·过时信息（旧票价、已停售票券）——明确标注「已作废」。
- 日本目的地的美食数据用 `tools/scrape_tabelog.py` 抓食べログ真实数据（`rankings` / `search` / `shops` 三个子命令，输出到 `research/tabelog_*.json`）。餐厅一律用真实评分，禁止编造。
- 图片用 `tools/fetch_commons_images.py` / `tools/fetch_food_images.py` 从 Wikimedia Commons 抓 CC0/CC BY/CC BY-SA 授权图，自动写 credits.json。**只用自由授权图**，图注里写明作者与授权。
- 已有工具：`tools/meal_data.py` + `tools/build_meal_page.py` 把餐饮数据按餐次重排成 HTML 片段。新目的地可仿照 `tools/build_nantong.py` 写构建脚本，数据与页面分离。

## 内容硬要求

- **货币**：出境游页面顶部必须声明「`¥` = 日元」还是人民币，并给出换算（注明汇率日期）；每个价格都写 `¥1,650（≈72 元）` 双币格式。国内游直接用「元」。
- **核对日期**：页脚写「攻略整理：YYYY 年 M 月 D 日 · 价格以官网为准」。
- **每个 POI 都要有**：营业/开放时间、定休日、门票（双币）、怎么去（几站/几分钟/多少钱）、注意事项。旺季限定信息（红叶见顷、夜间拝観、灯光季）必须带年份和具体日期区间。
- **行程节奏**：抵达日就近热身 → 中段最重 → 离开日上午收尾；体力星级 ★ 标注；明确「最后一天没有购物时间」之类的硬约束倒推。
- **美食按餐次排**（不是按品类列表）：每个 Day 内的「吃什么」按 早饭/午饭/下午/晚饭/夜宵 排列，每个时段写清「这时候你人在哪」；正餐要有品类多样性，并考虑当天定休（如「今天是周四，X 店休」）。
- **餐厅卡片字段**：食べログ评分 + 评价条数 + 好评率（最新约 20 条里 ≥3.5 的占比 + 抽样均分）+ 推荐指数 ★1–5 + 招牌 + 营业/定休 + 付款方式（只收现金要醒目）+ 怎么去 + 顺路安排 + **一条真实好评 + 一条真实差评/吐槽**（注明「食べログ 用户 · 分数 · 日期」，机翻只做断句整理，不改写）。
- **撤下名单**：复查后评分/好评率不够的店不删除，集中列进「复查后撤下推荐」区块，写明真实分数和撤下原因——这是本攻略的信用机制，必须有。
- **避坑清单**：10–17 条，只写这趟真的会踩的（定休日撞上行程、出口搞混、制度变化、旧攻略作废信息、天气/日落时间）。
- **弹窗底部必须有来源链接**（`src` 字段），A 级信息链到官网。

## 页面结构（区块顺序固定）

1. `.banner`：标题 + 日期 + 住宿 + 货币声明 + slogan 胶囊。
2. `.topnav` 吸顶锚点导航。
3. `#plan` 一句话规划：核心思路（以 X 为圆心……）+ 日期×主题×主线×体力 总览表 + 季节期望值管理（如红叶）。
4. `#hotel` 住宿与周边：酒店/街区 spot 卡 + 「去各处怎么走」逐条列出站数与票价。
5. `#d1`…`#dN` 每天一个 `.day`：头部 `.day-head`（d1–d5 五色轮换）→ `.geo` 为何这样走 → `.timeblock` 时间轴（时刻/时长/做什么/为什么，换乘写清站数、票价、出口编号）→ 「点这些卡片」`.spot` → 「吃什么」`.meals` 餐次时间轴（`.mcat` 品类分组 + `.scard` 店铺卡：封面图、★ 徽章、好评率徽章、档位徽章、图版权署名）。
6. `#pass` 交通票券：先给换算速查表，再每券一张 spot 卡；明确「什么情况下买哪个才划算」「哪个已停售/用不上」。
7. `#food` 评分数据说明（教读者怎么念食べログ分数）+ 撤下名单 `.demote`。
8. `#tips` 避坑清单。
9. `#precheck` 行前必查：A/B/C/D 来源分级 + 必做事项。
10. `#gallery` 图集：这趟会看到的画面，每张带作者/授权署名。
11. `.foot` 页脚：整理日期 + 数据等级声明。

## 弹窗系统（MODALS）

页面底部一个 `<div class="modal">` + `<script>const MODALS = {...}</script>`。所有 `.spot`/`.scard`/`.dcard`/`.lab` 通过 `data-modal="id"` 打开；`id` 以 `f-` 开头的走美食弹窗排版（评分面板 + 好评/差评卡 + 同品类跳转），其余走通用排版（badge + 头图 + kv + 推荐理由 + 避坑 + 来源）。支持 `#id` 深链直接打开弹窗。

- 通用条目字段：`tone(d1–d5), ic, t, s, tag[], img[src,说明,原图链接?], rows[[k,v]…], rec[], pit[], shop[], src[[名称,url]…]`。
- 美食条目（`f-`）额外字段：`cat`（品类，用于「同品类其他选择」跳转）；`rows` 固定含 人均/口碑/推荐指数/招牌/营业/定休/座位/预约/付款/怎么去/顺路；`shop` 放 `["真实评价 · 正面","引文 —— 食べログ 用户（4.0 分 · 2026/08）"]` 两条。
- id 命名：`hotel-main`、`area-*`、`spot-*`、`pass-*`、`pit-*`、`food-*`（点单指南类）、`f-*`（具体店）。

## 样式注意事项

- 配色变量：`--shu:#b4472f`(朱)、`--ai:#3e6f9e`(蓝)、`--gold:#c99a3f`、`--green:#2e7d5b`、`--cream:#faf7f2` 底；`.day-head`/`.modal-head` 用 d1–d5 五色渐变。
- 徽章：`.badge.g` 绿=推荐/必去，`.o` 金=备选/注意，`.r` 红=撤下/别踩坑，`.b` 蓝=顺路/免费。
- ⚠️ 已知坑：封面上的 `.tier` 档位徽章样式必须限定在 `.scard .cover` 内（见 CSS 注释），裸写会压塌 `#precheck` 的来源分级网格。
- 移动端：`@media(max-width:600px/700px)` 已有适配，新增组件记得补。
